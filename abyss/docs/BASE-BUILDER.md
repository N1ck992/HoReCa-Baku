# Конструктор базы (батискаф) — устройство

Дополнение №71, этап 1. Источники вдохновения — Emperor: Rise of the Middle Kingdom (свободная планировка)
и Kenshi (добыча, переработка, склады по материалам, списки работ героев). Числа и названия — черновик.

## Главный принцип

Готовой базы нет. Капсула — пустой корпус: кабина, жилой отсек, шлюз. Всё остальное — решения игрока:
где отсеки, какого размера, как соединены, где станки и склады, кто чем занят. Два игрока с одинаковым
стартом получают разные базы.

## Слои кода

| Файл | Что делает | Зависит от экрана? |
|---|---|---|
| `js/data/base.js` | Корпус, ядро капсулы, каталог чертежей `BLD-`, россыпи реголита | нет |
| `js/base/grids.js` | Строительные сетки `GRID-` как сменные модули | нет |
| `js/base/base-sim.js` | План, проверки размещения, склады, задачи героев, время, сохранение | **нет** — можно запускать на сервере |
| `js/base/base-view.js` | Капсула из плана, рисование поверх сцены, карточки, адаптер к игре | да |
| `js/base/base-build.js` | Режим стройки: каталог, призрак, правка, снос | да |
| `js/iso/iso-base.js` | Фигуры героев следуют за симуляцией | да |

Симуляция знает остальную игру только через адаптер `setExt`: шкафчики экипажа (`count/take/give`)
и кто сейчас на базе (`present`). Её состояние — простой JSON (`BaseSim.state()`), задачи героев —
тоже данные, поэтому состояние можно сохранить в любой момент и продолжить где угодно.

## Онлайн и офлайн

База живёт по реальному времени. Сейчас состояние хранится в браузере (`localStorage`, ключ
`abyss_base_v1`), сохраняется каждые 5 с и при закрытии; при возвращении `load()` досчитывает
отсутствие шагами по секунде (до 24 ч, работают те, кто был на базе при уходе). Час — около 30 мс.

Для онлайна тот же `base-sim.js` выполняется на сервере: сервер хранит состояние, по запросу игрока
досчитывает время с последнего расчёта и отдаёт состояние; приказы игрока (поставить, снести, назначить,
отнести, автохранение) — те же функции `place / modify / remove / assign / order / setRack`.

## Правила плана (сетка `GRID-001`)

- Помещение — прямоугольник клеток в пределах корпуса, размер — в пределах чертежа.
- Между помещениями — ровно одна клетка стены; в общей стене сам появляется проход (1–2 клетки).
- Новое помещение должно примыкать к стоящему; все помещения связаны проходами со шлюзом.
- Устройство — внутри построенного помещения, на свободном полу, не перекрывая проходы и доступ к другим.
- Поставленное — каркас: нужны материалы и работа строителей. Перестройка построенного засчитывает
  вложенное, недостающее довозят, работы — треть.
- Снос: построенное возвращает половину, каркас — всё принесённое; содержимое — в приёмник.

## Работа героев

У каждого героя — список работ по приоритету: устройство (станок), «Переноска», «Стройка».
Перед списком — приказы игрока «отнести на стеллаж». Задача — цепочка шагов: идти, взять, идти,
положить, работать. Путь — по клеткам плана (8 направлений), время = длина / 1,8 клетки в секунду.
Резервы не дают двум героям нести одно и то же.

- **Станок:** нет сырья на входе — работник несёт со стеллажа этого сырья; есть — работает;
  выход полон — уносит на стеллаж с автохранением продукта, а если такого нет — станок встаёт («!»).
- **Переноска:** из приёмника и с выходов станков — на стеллажи с автохранением.
- **Стройка:** носит материалы на каркасы (стеллажи, шкафчики экипажа) и строит.

## Энергия и электросеть (№72)

- Источники: реактор капсулы (ядро, 8/с), турбина течения (в среднем 4/с, колеблется). Батареи копят.
- Сеть — кабели (`S.cables`), связанные по соседним клеткам, плюс устройства, к стороне которых примыкает кабель.
  Устройство к устройству ток не передаёт. Сети считаются раздельно (`networks()`, кэш сбрасывается при смене плана).
- Каждый шаг времени (`power(dt)`): выработка сети + заряд батарей → станкам, которые сейчас работают,
  по приоритету (3 → 1); остаток заряжает батареи, нехватку покрывают батареи. Станок без энергии не продвигается,
  через 4 с работник уходит (пометка «нет энергии»), планировщик не посылает к станку без сети.
- Уровни устройств: `levels` в чертеже, `par(d)` — параметры с учётом уровня. Улучшение — каркас поверх
  устройства (`upTo`, `need/got/work`), пока идёт — устройство стоит.

## Новая сетка

Добавить запись в `AB.BaseGrids.define({...})` с теми же функциями: `cells` (какие клетки капсулы
занимает фигура), `snap`, `overlap`, `apart`, `door` (проход между двумя фигурами), `outline`.
Мир капсулы (ходьба, пути, отрисовка) всегда на квадратных клетках — сетка переводит фигуры в них.
