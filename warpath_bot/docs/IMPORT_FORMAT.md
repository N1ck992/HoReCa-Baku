# Формат импорта данных

Импорт выполняется администратором: отправьте боту файл `.json` или `.csv` в личном чате
(или `python manage.py import FILE` на сервере). Шаблоны: `data/import_templates/`,
в боте — команда `/templates`.

## Порядок и гарантии

1. **Предпроверка** — файл разбирается и проверяется, база не меняется. Бот показывает
   отчёт: сколько записей принято/отклонено и почему.
2. **Применение** — только кнопкой «✅ Применить» и только если отклонённых записей нет.
   Всё записывается в одной транзакции: при любой ошибке база остаётся как была.
3. **Защита от перезаписи** — запись с уже существующим кодом считается конфликтом.
   Обновить существующие записи можно только отдельной кнопкой
   «🔁 Применить с обновлением существующих» (или `--update` в консоли). При обновлении
   билда его состав и источники заменяются данными из файла.
4. Все запуски сохраняются в `import_runs`, применения — в журнал `admin_audit_log`.
   Ошибки последних импортов: «🧾 Ошибки импорта» в админ-меню.
5. Незаполненные заглушки шаблона вида `<...>` отклоняются — шаблон нельзя
   импортировать случайно.

Ограничения: файл до 1 МБ, кодировка UTF-8.

## JSON

Корень — объект. Все разделы необязательны, но хотя бы один должен быть непустым.
Записи могут ссылаться на сущности/источники/версии из этого же файла или уже существующие в базе.

```json
{
  "game": "warpath",
  "game_versions": [...],
  "entities": [...],
  "sources": [...],
  "builds": [...]
}
```

### `game` (обязательно)
Код игры, уже существующей в базе. Сейчас — только `warpath`.

### `game_versions[]`
| Поле | Обяз. | Формат |
|---|---|---|
| `version` | да | буквы, цифры, `.`, `-`, пробел; до 40 символов |
| `released_at` | нет | `ГГГГ-ММ-ДД` |
| `notes` | нет | текст до 1000 символов |

Существующая версия не дублируется (действие `exists`).

### `entities[]` — игровые сущности
| Поле | Обяз. | Формат |
|---|---|---|
| `type` | да | `unit_class` (тип войск/техники), `purpose` (задача), `commander`, `unit`, `skill` или любой другой тип: латиница в нижнем регистре и `_` |
| `code` | да | уникален в пределах типа: `a-z 0-9 _ - .`, до 64 символов |
| `name` | да | отображаемое название, до 120 символов |
| `attributes` | нет | объект с любыми характеристиками, специфичными для игры |
| `is_test` | нет | `true` для тестовых записей |

Поиск использует типы `unit_class`, `purpose` и `commander`. Другие типы можно
использовать в составе билда.

### `sources[]` — источники
| Поле | Обяз. | Формат |
|---|---|---|
| `code` | да | уникальный код |
| `title` | да | название источника |
| `url` | `url` или `description` | `http(s)://...` |
| `description` | — | что именно взято из источника (если нет URL — обязательно) |
| `publisher` | нет | автор/издатель |
| `retrieved_at` | нет | дата получения данных `ГГГГ-ММ-ДД` |

### `builds[]` — билды
| Поле | Обяз. | Формат |
|---|---|---|
| `code` | да | уникальный код билда |
| `title` | да | до 120 символов |
| `unit_class` | да | код сущности типа `unit_class` |
| `purpose` | да | код сущности типа `purpose` |
| `game_version` | для verified | версия из `game_versions` или базы |
| `description` | нет | краткое описание |
| `components[]` | нет | состав: `{"role": "commander", "entity": "код"}` или `{"role": "other", "label": "текст"}`; `notes` — примечание; `entity_type` — если тип сущности отличается от роли |
| `upgrade_priority` | нет | список шагов (или строка через `\|`) |
| `tactics` | нет | текст |
| `strengths`, `weaknesses` | нет | списки строк |
| `verification_status` | нет | `needs_review` (по умолчанию), `verified`, `possibly_outdated`, `outdated`, `user_suggestion` |
| `status_reason` | для verified | обоснование статуса |
| `last_verified_at` | для verified | `ГГГГ-ММ-ДД` |
| `is_test` | нет | `true` — тестовая запись |
| `sources[]` | для verified | `{"source": "код", "claim": "что подтверждает", "confirms": true, "checked_at": "ГГГГ-ММ-ДД"}` |

**Правила статуса `verified`** (иначе запись отклоняется): не тестовая, есть хотя бы один
источник с `confirms: true`, указаны `game_version`, `last_verified_at` и `status_reason`.
Рабочий (не тестовый) билд не может ссылаться на тестовые сущности.

Лимиты: тексты до 3000 символов, списки до 30 пунктов по 500 символов.

## CSV

Тип CSV определяется по заголовкам. Первая строка — заголовки, разделитель — запятая,
значения с запятыми берите в кавычки. Колонка `game` необязательна (по умолчанию `warpath`).
Импортируйте в порядке: версии → сущности → источники → билды.

| Файл | Обязательные колонки | Дополнительно |
|---|---|---|
| версии | `version` | `released_at`, `notes` |
| сущности | `type`, `code`, `name` | `is_test` |
| источники | `code`, `title`, `url` | `publisher`, `retrieved_at`, `description` |
| билды | `code`, `title`, `unit_class`, `purpose` | `game_version`, `description`, `commanders` (коды через `;`), `units` (`;`), `other_components` (`;`), `upgrade_priority` (`\|`), `tactics`, `strengths` (`\|`), `weaknesses` (`\|`), `verification_status`, `status_reason`, `last_verified_at`, `is_test` (`true/false`), `source_codes` (`;`), `source_claim` |

CSV не поддерживает `attributes` у сущностей и отдельные утверждения для каждого источника —
для этого используйте JSON.
