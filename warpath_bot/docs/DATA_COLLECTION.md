# Процедура получения и проверки игровых данных

Цель — наполнять базу только данными, происхождение которых можно проверить.
Бот поставляется **без игровых билдов**: никакие сборки не придуманы «для примера».
Единственные встроенные записи — тестовые (🧪), они скрыты от пользователей.

## 1. Какие источники допустимы

| Тип источника | Допустим | Как использовать |
|---|---|---|
| Официальные патчноуты, анонсы, сайт и соцсети разработчика | да | основа для версий игры и фактов о механиках |
| Описания в самой игре (скриншот, сделанный админом) | да | указать в `description` источника дату и версию клиента |
| Публичные гайды сообщества (сайты, видео, посты) | да, со ссылкой | пересказ своими словами + ссылка; статус не выше `needs_review` без подтверждения |
| Опыт альянса/экспертов | да | источник с `description` (кто, когда, на каком аккаунте проверено) |
| Платные гайды, закрытые базы, материалы за авторизацией | **нет** | не копировать и не обходить ограничения |

Не копируйте чужие тексты целиком — храните собственные структурированные описания и ссылку.

## 2. Пошаговая процедура

1. **Зафиксировать версию игры.** Добавить её в `game_versions` (или `/game_update <версия>` —
   это заодно пометит старые проверенные билды как «возможно устарело»).
2. **Зарегистрировать источник** в `sources`: `code`, `title`, `url` (или `description`),
   `publisher`, `retrieved_at` — дата, когда данные были получены.
3. **Разложить информацию на утверждения.** Для каждого билда в `sources[].claim` указать,
   *что именно* подтверждает источник (например, «состав и назначение», «приоритет прокачки»).
   Если источник говорит об этом лишь косвенно — `confirms: false`.
4. **Выбрать статус** по таблице ниже и записать `status_reason`.
5. **Заполнить шаблон** (`/templates`) и отправить файл боту → изучить отчёт предпроверки.
6. **Применить** импорт. Проверить карточку командой `/build_admin <id>`.
7. **После обновления игры** выполнить `/game_update <версия>`, затем перепроверить билды
   со статусом ⏳ и вернуть `verified` командой `/status <id> verified <обоснование>`.

## 3. Критерии статуса

| Статус | Когда ставить |
|---|---|
| `verified` ✅ | есть подтверждающий источник (`confirms: true`) **и** подтверждение актуальности для указанной версии игры: второй независимый источник или проверка в игре. Обязательны `game_version`, `last_verified_at`, `status_reason`. Бот не даст поставить статус без этих полей |
| `needs_review` ⚠️ | данные взяты из источника, но не перепроверены; или источник один и неофициальный |
| `possibly_outdated` ⏳ | вышла новая версия игры, повторная проверка ещё не проведена |
| `outdated` ❌ | известно, что данные неактуальны (в поиске не показываются) |
| `user_suggestion` 💬 | предложение игрока без проверки (в поиске не показывается) |

«Найдено в интернете» само по себе **не** основание для `verified`.

## 4. Чек-лист перед импортом

- [ ] У каждого билда есть источник; у источника — ссылка или описание и дата получения.
- [ ] Указана версия игры, к которой относятся данные.
- [ ] Тексты написаны своими словами, без копирования чужих гайдов.
- [ ] `verified` только при выполнении всех условий из таблицы.
- [ ] Нет заглушек `<...>`, коды латиницей в нижнем регистре.
- [ ] Предпроверка показала 0 отклонённых записей.

## 5. Автоматизированный сбор (на будущее)

Автоматический парсер **не реализован** намеренно: без согласованного списка разрешённых
источников он не может получать реальные данные, а имитация обновления недопустима.
Требования к будущему сборщику:

- только публичные источники, разрешённые их правилами (Terms of Service, `robots.txt`);
- никакого обхода авторизации, CAPTCHA, лимитов и других средств защиты;
- сохранять URL, дату получения и контрольную сумму исходной страницы;
- на выходе — файл импорта со статусом `needs_review`, который проверяет человек;
  сборщик никогда не ставит `verified` сам;
- при недоступности источника — явная ошибка в отчёте, а не «успешное обновление».

## 6. Что нужно от владельца проекта

- Список источников, которым вы доверяете (официальные каналы Warpath, гайды, эксперты альянса).
- Решение, кто вправе ставить статус `verified` (сейчас — любой из `ADMIN_IDS`).
- Первые реальные данные: можно начать с 1–2 типов войск и заполнить JSON-шаблон.
