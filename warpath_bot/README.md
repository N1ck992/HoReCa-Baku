# Warpath Assistant — Telegram-бот для подбора билдов

Бот помогает подобрать билд для Warpath по типу войск, задаче и командиру.
Все рекомендации берутся только из базы с указанием источника и статуса проверки —
бот **не придумывает** сборки и честно сообщает, если подходящих данных нет.

> Проект живёт в подкаталоге `warpath_bot/` и никак не связан с HoReCa-ботом
> в корне репозитория. Все команды ниже выполняются из `warpath_bot/`.

## Что умеет первая версия

- Главное меню на inline-кнопках: игра, поиск, база знаний, избранное, профиль, помощь.
- Пошаговый поиск: игра → тип войск → задача → командир (если есть в данных) → результаты.
  Варианты строятся только из реально существующих билдов.
- Карточка билда в 4 частях (состав / тактика / плюсы-минусы / источники), статус проверки
  виден всегда: ✅ проверено, ⚠️ требует проверки, ⏳ возможно устарело. Устаревшие и
  пользовательские предложения в поиск не попадают. Тестовые записи помечены 🧪 и по
  умолчанию скрыты.
- Избранное (у каждого пользователя своё), профиль с тарифом и остатком лимита.
- Работа в группах: команды `/build`, `/menu`, `/help`; бот не реагирует на обычные
  сообщения и не требует прав администратора группы. Профиль и избранное — через кнопку
  «Открыть в личном чате».
- Администрирование (только Telegram ID из `ADMIN_IDS`, только в личке):
  состояние БД, статистика, импорт JSON/CSV с предпроверкой и подтверждением,
  смена статусов, пометка устаревшими, редактирование, журнал, ошибки импорта,
  тестовые подписки без оплаты.
- Тарифы `free` / `premium` / `group_premium` и суточный лимит поисков — проверяются
  централизованно в `services/access_service.py`. Реальные платежи не подключены.

## Быстрый старт (локально)

```bash
cd warpath_bot
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # впишите BOT_TOKEN и ADMIN_IDS
python manage.py check-config # проверка настроек (токен не выводится)
python bot.py
```

Для проверки интерфейса без реальных данных:

```bash
python manage.py load-demo     # загружает ТЕСТОВЫЕ записи (🧪)
# и в .env: SHOW_TEST_DATA=true
```

На рабочем боте `SHOW_TEST_DATA` должен быть `false`.

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `ADMIN_IDS` | нет | Telegram ID админов через запятую |
| `DATABASE_PATH` | нет | путь к SQLite (на хостинге — на постоянном томе, напр. `/data/warpath.db`) |
| `SHOW_TEST_DATA` | нет | `true` — показывать тестовые записи 🧪 (только для разработки) |
| `FREE_DAILY_SEARCH_LIMIT` | нет | лимит поисков в сутки на бесплатном тарифе, `0` — без лимита (по умолчанию 50) |
| `HEALTH_PORT` | нет | порт HTTP health-check `/health` |
| `LOG_LEVEL` | нет | `INFO` по умолчанию |

## Проверка работоспособности

- `python manage.py health` — целостность базы, миграции, статистика (код 0 = ок).
- `GET /health` (если задан `HEALTH_PORT`) — `200 {"status":"ok"}` во время работы,
  `503` если база недоступна или polling не запущен.
- В Telegram админу: `/health`.

Коды выхода `bot.py`: `2` — ошибка конфигурации, `3` — Telegram отклонил токен,
`4` — нет связи с Telegram API. Остановка по SIGTERM/SIGINT корректная.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты используют временные базы и имитацию Telegram API — токен и сеть не нужны.

## Структура

```
bot.py              точка входа (polling, health-check, корректное завершение)
app.py              сборка диспетчера и сервисов
manage.py           служебные команды: init-db, health, import, load-demo, check-config
config.py           настройки из окружения
models.py           доменные модели и статусы
database/           подключение, транзакции, миграции (migrations/*.sql)
repositories/       SQL-доступ (только параметризованные запросы)
services/           бизнес-логика: поиск, доступ/тарифы, импорт, администрирование
handlers/           обработчики Telegram: start, builds, profile, admin, errors
keyboards/          inline-клавиатуры и callback-данные
views/              тексты карточки билда
locales/            тексты интерфейса (ru; готово к добавлению других языков)
bot_utils/          безопасные вызовы Telegram API, middleware
data/import_templates/  шаблоны импорта
data/test_fixtures/     тестовые данные (🧪)
docs/               формат импорта, развёртывание, сбор данных
tests/              автотесты
```

## Безопасность

- Токен только в переменных окружения; `.env` в `.gitignore`; в логах токен маскируется.
- Если токен когда-либо попал в Git — удаления из файла недостаточно: перевыпустите его
  в @BotFather (`/revoke`) и обновите переменную на хостинге.
- Админ-функции: проверка Telegram ID + только личный чат.
- Все SQL-запросы параметризованы; имена полей при редактировании — из белого списка.
- Пользователю ошибки показываются без внутренних деталей.

## Переход на PostgreSQL

SQL изолирован в `repositories/`, `services/import_service.py` и `database/`. Для перехода:
переписать `database/connection.py` (драйвер, плейсхолдеры `?` → `%s`/`$1`), адаптировать
миграции (`INTEGER PRIMARY KEY` → `BIGINT GENERATED ... AS IDENTITY`). Бизнес-логика
и обработчики не меняются. `ON CONFLICT` уже используется в совместимой с PostgreSQL форме;
места с `cursor.lastrowid` нужно будет заменить на `RETURNING id`.
